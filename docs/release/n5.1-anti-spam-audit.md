# N5.1 — Audit anti-spam baseline

Scope: enforcement Socket.IO for `find-partner`, `send-message`, and `report`.
This is an observed baseline, not a change to N4 enforcement.

| Area | Baseline | Evidence |
| --- | --- | --- |
| Guest and account limits | Both use a persistent principal. Match: 20 per 60 seconds with 60/300/900-second escalation; message: 12 per 10 seconds with 30/120/600-second escalation; report: 5 per hour with 300/900/3600-second escalation. Skip cooldown is 10 seconds for guests, 3 seconds for free accounts, and none for premium. | `lib/moderation-rate-limit.js`, `lib/chat.js` |
| Socket.IO events | The distributed limiter applies to `find-partner`, `send-message`, and `report`. Read receipts, guest-session refresh, leave, and direct-chat events have no equivalent rate policy. | `lib/chat.js` |
| Cross-replica persistence | PostgreSQL stores a window per `(principal_type, principal_id, action)`. A transaction and row lock serialize counter and escalation updates across replicas. Escalation expiry is persisted. | `database/migrations/009_n4_moderation_foundation.sql`, `database/migrations/011_n4_distributed_rate_limits.sql`, `test/integration/moderation-rate-limit.test.js` |
| Reconnect and reset | Reconnects and multiple tabs retain a principal-scoped rate window while PostgreSQL is available. A window and escalation reset only after expiry. Queue, pairing, and skip state are still process-local socket state. | `lib/moderation-rate-limit.js`, `lib/chat.js` |
| Duplicate and flood controls | The current message quota is the only flood control. There is no duplicate normalization, message fingerprint, link-flood threshold, repeated-character threshold, sustained-burst policy, or message idempotency key. `BANNED_WORDS` is a case-insensitive substring fallback, not spam detection. | `lib/chat.js` |
| Client feedback | The server returns a generic message and `retryAfterSeconds` for rate rejection. The client currently ignores the retry value, removes one optimistic message, and adds a system line. Skip has its own countdown. A reconnect returns to setup rather than resuming queue/chat state. | `lib/chat.js`, `public/js/chat-client.js`, `public/i18n/en.json` |
| Logs and audit | Allow, deny, and escalation decisions are not logged or audited. Error logs are minimised by `safe-log` and do not include message bodies or raw network data. Message bodies are stored only as normal conversation data; report evidence has its separate retention path. | `lib/safe-log.js`, `lib/chat.js`, `database/migrations/009_n4_moderation_foundation.sql` |

## N5.2 guardrails

- Keep the server authoritative and the cross-replica state PostgreSQL-backed.
- Add only narrowly-scoped duplicate/burst signals with expiry; do not make
  `BANNED_WORDS` broader or introduce opaque content scoring.
- Return generic user feedback plus a bounded retry value; never disclose a
  detection rule.
- If telemetry is necessary, record minimised action/outcome/expiry metadata
  only. Never write a message body, raw IP address, device fingerprint, or a
  derived message fingerprint to logs or audit records.
- Cover reconnect, multiple sockets for one principal, replica handoff, and
  out-of-order optimistic client failures in tests before changing policy.
